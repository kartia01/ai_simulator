## 1. 사용자 역할

| 역할 | 설명 |
|---|---|
| Admin | 시스템 관리자. 모든 사용자 계정 관리, 전체 데이터 열람 |
| User | 일반 사용자. 자신의 프로젝트 및 시뮬레이션 관리 |

> **Phase 1 (베이스라인)**: 실제 인증 없음. 로그인 화면에서 역할 선택 후 바로 진입.

### 권한 매트릭스

| 기능 | Admin | User |
|---|---|---|
| 사용자 계정 생성·삭제 | ✅ | ❌ |
| 모든 사용자 채팅 기록 열람 | ✅ | ❌ |
| 사용자 사용량 모니터링 | ✅ | ❌ |
| 프로젝트 생성 | ✅ | ✅ |

| 프로젝트 멤버 초대 [7/8 목표] | ✅ | ✅ (Owner만) |

## 2. 기능 요구사항

### FR-01 인증 및 접근 제어

#### FR-01-1 로그인 UI [베이스라인]
- 로그인 화면에서 역할(관리자 / 사용자)을 선택하면 실제 인증 없이 해당 역할로 앱에 바로 진입
- Zustand store에 선택된 역할을 저장하여 UI 접근 제어 수행
- 백엔드 인증 없음

#### FR-01-2 실제 인증 [7/8 목표, 구현 여부 미정]
- 이메일 + 비밀번호 방식
- OAuth2/JWT — Access Token(1시간) + Refresh Token(30일)
- 로그아웃 시 Refresh Token 무효화
- Token Rotation: 갱신 시 Access + Refresh 동시 재발급

---

### FR-02 광고 입력

#### FR-02-1 이미지 광고 업로드 [베이스라인]
- 지원 형식: JPG, PNG, WebP, GIF
- 최대 파일 크기: 10MB
- AWS S3 저장 후 시뮬레이션 파이프라인으로 전달

#### FR-02-2 텍스트 광고 입력 [베이스라인]
- 광고 문구 직접 입력 (헤드라인, 본문, CTA 등)

#### FR-02-3 영상 광고 업로드 [7/8 목표]
- 지원 형식: MP4, MOV, AVI
- 최대 파일 크기: 100MB, 최대 15초
- **파일 업로드 방식만** 지원 (동영상 URL 입력 제거)
- ffmpeg 프레임 추출 + Whisper API 음성 텍스트 변환

### FR-03 시뮬레이션 (핵심)

광고 분석 → 페르소나 생성 → 반응 시뮬레이션 → 결과 집계 → 성과 예측 → 개선안 생성을 하나의 통합 파이프라인으로 실행한다.

→ 파이프라인 상세: [시뮬레이션.md](시뮬레이션.md)

#### FR-03-1 광고 분석 (Stage 1)
- 구성 요소 자동 추출: 문구(헤드라인/본문/CTA), USP, 감정 요소, 색상, 레이아웃, 브랜드 요소
- 이미지/텍스트/영상 모두 동일한 분석 스키마 출력
- 분석 신뢰도 점수 포함

#### FR-03-2 페르소나 생성 (Stage 2)
- 3계층 속성: Layer 1(인구통계) + Layer 2(심리통계) + Layer 3(서사적 컨텍스트)
- 기본 20명, UI에서 수량 조절 가능
- Temperature 분산 할당으로 다양성 강제

#### FR-03-3 반응 시뮬레이션 (Stage 3)
각 페르소나의 신호 생성:

| 필드 | 타입 | 설명 |
|---|---|---|
| attention | float 0~1 | 주목도 |
| sentiment | float -1~1 | 호감도 |
| click_intent | bool | 클릭 의향 |
| conversion_intent | bool | 구매 전환 의향 |
| comprehension | float 0~1 | 메시지 이해도 |
| recall | float 0~1 | 브랜드 기억 가능성 |
| reasoning | string | 반응 이유 |
| confidence | float 0~1 | 시뮬레이터 확신도 |

#### FR-03-4 결과 집계 (Stage 4)
- IQR 방식 이상치 감지 및 제거
- 세그먼트별 통계 (연령대, 성별, 소득 수준)

#### FR-03-5 성과 예측 (Stage 5)
CTR Prediction, Purchase Intent Score, Audience Fit Score, Rejection Rate, Trust Score, Confidence Score

#### FR-03-6 개선안 생성 (Stage 6)
문제점 분석(심각도별), 카피 개선안 3가지, CTA 제안, 타깃별 수정안

#### FR-03-7 SSE 실시간 진행률
- 이벤트: `progress`, `stage_complete`, `milestone`, `completed`, `error`

#### FR-03-8 시뮬레이션 결과 리포트
- 웹 화면 (채팅창 스트리밍) + PDF 출력 [베이스라인]
- 리포트 상단 면책 문구 필수

#### FR-03-9 Debate Agent [7/8 목표, 미정]
- Round 1: 긍정 페르소나 평가 → Round 2: 부정 페르소나 반박 → Round 3: 중재 종합
- 보정 전/후 점수 모두 리포트에 포함

## 3. 비기능 요구사항

### NFR-01 응답 속도
- 시뮬레이션 결과 (20명 기준): 1분 이내
- API 일반 응답: 200ms 이내 (p95)
- SSE 첫 이벤트 수신: 3초 이내

### NFR-02 확장성

| 단계 | 페르소나 수 | 처리 방식 |
|---|---|---|
| Phase 1 | 10~50명 | asyncio Background Task |
| Phase 2 | 50~200명 | Semaphore 동시성 제어 |
| 장기 | 200~1,000명 | AWS SQS + ECS Fargate Worker |

### NFR-03 신뢰성
- 결과에 근거(긍정/부정 요인, Confidence Score) 포함
- 이상치 감지 및 제거 후 집계
- 리포트 상단 면책 문구 필수

### NFR-04 재현성
- seed 기반 페르소나 생성으로 재현 가능
- LangSmith로 모든 단계의 Input/Output/Prompt/Model 기록

### NFR-05 비용
- 시뮬레이션 1회 비용 (20명): $0.10 이하
- LLM 비용 DB 기록

### NFR-06 보안
- Phase 1: 클라이언트 사이드 역할 선택 (실제 보안 없음)
- Phase 2: JWT Access + Refresh Token (미정)
- 기밀 데이터 평문 로그 금지

### NFR-07 다크모드
- 시스템 전체 다크/라이트 모드 토글 (헤더에서 전환)

### NFR-08 AI 추적성
- LangSmith로 모든 LLM 호출 추적
- 단계별 Input/Output/Prompt/Model/Latency/Error 기록
→ 상세: [AI평가체계.md](AI평가체계.md)
