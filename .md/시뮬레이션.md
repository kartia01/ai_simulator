## 1. 개요

**시뮬레이션**은 ClickMe의 핵심 기능이다. 광고 분석 → 페르소나 생성 → 반응 시뮬레이션 → 결과 집계 → 성과 예측 → 개선안 생성을 하나의 LangGraph 파이프라인으로 처리한다.

기존의 "광고 분석"과 "광고 시뮬레이터" 기능은 이 시뮬레이션으로 통합된다.

## 2. 파이프라인 전체 흐름

```
사용자 입력 (광고 이미지 / 텍스트 / 영상)
        │
        ▼
┌──────────────────┐
│  Stage 1         │  광고 분석 (Ad Analysis)
│  GPT-4o Vision   │  → AdAnalysisResult
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  Stage 2         │  페르소나 생성 (Persona Generation)
│  GPT-4o-mini     │  → PersonaSet (기본 20명)
└────────┬─────────┘
         │
         ▼ (병렬 처리)
┌──────────────────┐
│  Stage 3         │  반응 시뮬레이션 (Reaction Simulation)
│  GPT-4o-mini     │  → PersonaResponses
│  + Claude Haiku  │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  Stage 4         │  결과 집계 (Aggregation)
│  Python 통계      │  → AggregationResult (이상치 제거)
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  Stage 5         │  성과 예측 (Prediction)
│  Claude Sonnet   │  → PredictionResult (KPI, 펀넬)
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  Stage 6         │  개선안 생성 (Improvement)
│  Claude Sonnet   │  → ImprovementReport
└────────┬─────────┘
         │
         ▼
최종 결과 (PDF 리포트 + 채팅창 스트리밍)
```

모든 단계는 LangSmith로 자동 추적된다. → [AI평가체계.md](AI평가체계.md)

## 3. 단계별 Contract (Pydantic 스키마)

각 Stage는 `contracts/` 아래에 정의된 Pydantic 스키마를 I/O로 사용한다. 계약을 먼저 확정한 후 개발 시작.

### Stage 1: 광고 분석

```python
class AdInput(BaseModel):
    ad_id: str
    input_type: Literal["image", "text", "video"]
    storage_url: str | None          # 이미지/영상: S3 URL
    text_content: dict | None        # 텍스트: {headline, body, cta, ...}
    prompt_version: str = "v1.0"

class AdAnalysisResult(BaseModel):
    ad_id: str
    confidence: float
    text_analysis: TextAnalysis
    visual_analysis: VisualAnalysis | None
    strategic_analysis: StrategicAnalysis

class StrategicAnalysis(BaseModel):
    target_demographic: str
    purchase_stage_target: Literal["awareness", "consideration", "conversion"]
    usp: str
    key_message: str
```

---

### Stage 2: 페르소나 생성

```python
class PersonaGenRequest(BaseModel):
    simulation_id: str
    count: int = 20
    segment_distribution: dict[str, float] | None
    ad_analysis: AdAnalysisResult

class PersonaSet(BaseModel):
    simulation_id: str
    personas: list[Persona]

class Persona(BaseModel):
    persona_id: str               # "P_0001"
    segment: str
    attributes: PersonaAttributes
    temperature: float            # 다양성 제어
    seed: int                     # 재현성

class PersonaAttributes(BaseModel):
    # Layer 1: 인구통계
    age: int
    gender: str
    region: str
    occupation: str
    income_level: str
    education: str
    # Layer 2: 심리통계
    purchase_motivation: str
    info_search_style: str
    ad_response_tendency: str
    brand_loyalty: float
    price_sensitivity: float
    impulse_buying_tendency: float
    # Layer 3: 서사적 컨텍스트
    recent_purchase_experience: str
    current_concern: str
    trigger_words: list[str]
    rejection_words: list[str]
    current_emotion: str
```

### Stage 3: 반응 시뮬레이션

```python
class ReactionSimRequest(BaseModel):
    simulation_id: str
    ad_analysis: AdAnalysisResult
    personas: list[Persona]
    objective: Literal["awareness", "conversion"]

class PersonaResponses(BaseModel):
    simulation_id: str
    responses: list[PersonaResponse]

class PersonaResponse(BaseModel):
    persona_id: str
    producer_id: str              # 구현체 식별자 (예: "member_c_v2")
    signals: ReactionSignals
    reasoning: str
    confidence: float
    llm_model: str
    prompt_version: str
    tokens_used: int
    response_time_ms: int

class ReactionSignals(BaseModel):
    attention: float              # 0.0 ~ 1.0
    sentiment: float              # -1.0 ~ 1.0
    click_intent: bool
    conversion_intent: bool
    comprehension: float
    recall: float
```

## 4. LangGraph 파이프라인

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict

class SimulationState(TypedDict):
    ad_input: AdInput
    ad_analysis: AdAnalysisResult | None
    persona_set: PersonaSet | None
    persona_responses: PersonaResponses | None
    aggregation_result: AggregationResult | None
    prediction_result: PredictionResult | None
    improvement_report: ImprovementReport | None
    progress_queue: asyncio.Queue
    simulation_id: str
    objective: str

builder = StateGraph(SimulationState)
builder.add_node("ad_analysis", run_ad_analysis)
builder.add_node("persona_gen", run_persona_gen)
builder.add_node("reaction_sim", run_reaction_sim)
builder.add_node("aggregation", run_aggregation)
builder.add_node("prediction", run_prediction)
builder.add_node("improvement", run_improvement)

builder.set_entry_point("ad_analysis")
builder.add_edge("ad_analysis", "persona_gen")
builder.add_edge("persona_gen", "reaction_sim")
builder.add_edge("reaction_sim", "aggregation")
builder.add_edge("aggregation", "prediction")
builder.add_edge("prediction", "improvement")
builder.add_edge("improvement", END)

pipeline = builder.compile()
```

## 5. 팀 개발 구조 (6인)

### 모듈 디렉토리

```
ai-service/src/clickme_ai/
├── contracts/                 # 공통 I/O 스키마 (먼저 확정)
│   ├── ad_analysis.py
│   ├── persona_gen.py
│   ├── reaction_sim.py
│   ├── aggregation.py
│   ├── prediction.py
│   └── improvement.py
├── stages/                    # 팀원별 구현체
│   ├── ad_analysis/
│   │   ├── agent.py
│   │   ├── prompts.py
│   │   └── tests/
│   ├── persona_gen/
│   ├── reaction_sim/
│   ├── aggregation/
│   ├── prediction/
│   └── improvement/
├── pipeline.py                # LangGraph 통합
└── chat/
    └── agent.py
```

### 독립 개발 원칙

1. **계약 우선**: `contracts/` 스키마 확정 후 구현
2. **Fixture 제공**: `tests/fixtures/`에 mock 입력 데이터
3. **독립 실행**: 앞 Stage 없이 fixture로 단독 실행 가능
4. **인터페이스 준수**: `async def run(self, input) -> output` 시그니처

### 다중 구현체 비교 (`producer_id`)

동일 Stage를 여러 방식으로 구현하여 LangSmith에서 비교:
- `producer_id`로 구현체 식별
- 동일 입력 → 여러 구현체 실행 → LangSmith 비교 대시보드
