## 4. 데이터 흐름

### 시뮬레이션 요청 흐름

```
1. 사용자 → frontend: 광고 업로드
2. frontend → FastAPI: POST /api/simulations
3. FastAPI → S3: 파일 업로드
4. FastAPI → DB: simulations 레코드 생성 (status=pending)
5. FastAPI → Background Worker: 시뮬레이션 태스크 등록
6. FastAPI → frontend: 202 Accepted + simulation_id

7. frontend → FastAPI: GET /api/simulations/{id}/stream (SSE)
8. Background Worker → LangGraph: 파이프라인 실행
9. LangGraph Stage 완료마다 → asyncio.Queue: 이벤트 발행
10. FastAPI SSE → frontend: 진행률 스트리밍

11. 파이프라인 완료 → DB: 결과 저장
12. FastAPI SSE → frontend: completed 이벤트
13. frontend: 결과 화면 표시
```

### SSE 이벤트 타입

| 이벤트 | 데이터 |
|---|---|
| `progress` | `{stage, completed, total, percent}` |
| `stage_complete` | `{stage, durationMs}` |
| `milestone` | `{message}` |
| `completed` | `{simulation_id, result_url}` |
| `error` | `{message, stage}` |
| `ping` | (30초 간격 keepalive) |

## 5. Phase 1 인증 구조 (UI 전용)

**Phase 1 (베이스라인 6/12): 실제 인증 없음**

```
진입 페이지  →  로그인 페이지
                  [관리자로 진입] 버튼 클릭  →  /admin 진입
                  [사용자로 진입] 버튼 클릭  →  / (채팅창) 진입
```

- Zustand store에 선택된 역할(`admin` | `user`)과 더미 사용자 정보 저장
- 클라이언트 사이드 UI 접근 제어만 존재 (실제 보안 없음)
- 백엔드 인증 API 없음, JWT 없음, 토큰 없음
- DB의 `users`, `refresh_tokens` 테이블은 Phase 2용 스키마만 존재

**Phase 2 (7/8 목표): 구현 여부 미정**

OAuth2 + JWT 실제 인증 도입을 검토하나 구현 여부는 미정.

## 6. 비동기 처리 구조

### Phase 1: asyncio 인메모리

```python
# Background Task (FastAPI)
background_tasks.add_task(run_simulation, simulation_id, ad_input)

# 파이프라인 내 SSE 큐
state["progress_queue"] = asyncio.Queue()

# SSE 스트리밍
async def stream_simulation(simulation_id):
    queue = get_queue(simulation_id)
    while True:
        event = await queue.get()
        yield f"data: {json.dumps(event)}\n\n"
        if event["event"] in ("completed", "error"):
            break
```

### Phase 2: AWS SQS (향후)

```
FastAPI → SQS 메시지 발행 → Worker(ECS Fargate) → 결과 DB 저장 → SSE 폴링
```
